# Security

This is a static site with no backend, no accounts, no forms and no third-party
code. Its security posture is therefore mostly about what it *refuses* to do, and
about the two things it deliberately keeps out of a public repository.

## Reporting

If you find something, email the address shown under **Partner with us** on the
live site. Please do not open a public issue for anything that could identify a
summit venue — see the second section below for why.

## What the page enforces on itself

**Content Security Policy.** Every build carries a `<meta http-equiv="Content-Security-Policy">`
generated by `build.py`:

```
default-src 'none'; img-src 'self' data:; font-src 'self' data:;
style-src 'sha256-…'; script-src 'sha256-…' 'sha256-…' 'sha256-…';
connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'
```

- `default-src 'none'` — nothing loads unless a directive below allows it.
- The one `<style>` block and three `<script>` blocks are allowed **by SHA-256
  hash of their exact contents**, computed on the final HTML after every
  placeholder is resolved. Any script or style that is not byte-for-byte one of
  ours is refused. There is no `'unsafe-inline'` anywhere, which is also why the
  template contains no `style=""` attributes — they would be blocked.
- `connect-src 'none'` — the page cannot phone home. It has nothing to say.
- No external origin appears in any directive because the page loads nothing
  external: fonts and images are either bundled files or `data:` URIs.

**No injection surface.** The speaker grid is the only dynamic markup, and it is
built with `createElement`/`textContent`, never `innerHTML`. The data is static
and ours; the point is that no HTML-parsing path exists in the page at all.

**No tracking.** No analytics, no cookies, no third-party requests. The privacy
notice says so, and the CSP makes it true rather than merely claimed. The only
thing the page can store is a `localStorage` flag recording that the notice was
dismissed, and only if the visitor clicks *Accept*.

**Referrer.** `<meta name="referrer" content="no-referrer">`.

## What GitHub Pages cannot do, and what to do about it

Pages cannot set HTTP response headers. Two protections therefore cannot be
applied here and are **absent, not forgotten**:

| header | protects against | status |
|---|---|---|
| `Content-Security-Policy: frame-ancestors 'none'` | clickjacking (the site framed inside a hostile page) | not expressible in a `<meta>` CSP |
| `Strict-Transport-Security` | protocol downgrade | Pages serves HTTPS, but cannot send HSTS for a custom domain |

When the site moves to `globalpassportseries.com`, host it somewhere that can
send headers — Cloudflare Pages, Netlify, or Pages behind Cloudflare — and add
`frame-ancestors 'none'`, HSTS, `X-Content-Type-Options: nosniff` and
`Permissions-Policy` at that layer. `build.py` can then drop the `<meta>` CSP in
favour of the header, or keep both; they compose.

## The build pipeline

- `.github/workflows/pages.yml` pins every action to a **full commit SHA**, not a
  floating tag. A tag can be moved by whoever controls the action's repository;
  a SHA cannot. The trailing `# vN` comment records which release it is.
- The workflow token has `contents: read`, `pages: write`, `id-token: write` and
  nothing else.
- The deploy is **gated on the redaction audit** (`build.py --check`) and then
  re-checks the actual deploy candidate. A build that reintroduced a redacted
  string cannot reach the public URL.

## Two things this repository keeps out on purpose

The summits are invitation-only. Two pieces of information are removed from the
site so that uninvited people cannot act on it, and — because this repository is
public and git history is permanent — they are kept out of the repository too.
**docs/BRIEF.md §2 is the authoritative description; read it before committing.**

1. **Munich venue names.** Enforced by `build.py` as salted SHA-256 digests
   matched against every 1–4-word window of the built page. The plaintext list
   is gitignored (`redactions.local.txt`). A digest confirms a guess; it does not
   prevent one. It stops the far likelier failure — the list being read straight
   out of a public repo.
2. **The contact address.** Never written literally in the source. Stored as two
   base64 fragments and assembled at runtime; the build fails on any bare
   address pattern. This defeats scrapers that read raw HTML, which is most of
   them. It does not defeat a person or a headless browser, and nothing here
   claims it does.

Commit messages and pull-request text are as permanent as files and are not
covered by `.gitignore` or the audit. Keep the venue names out of those too.
